# 《战区识别库》内容与系统草案

> 系统代号：`TACTICAL INDEX // 战区识别库`  
> 玩家俗称：图鉴  
> 功能定位：提供即时、可靠、可操作的玩法信息。  
> 它回答“这是什么、会做什么、怎么使用或应对”，不负责讲完整历史。

## 1. 与《锚区档案》的区别

| 系统 | 回答的问题 | 文风 | 解锁重点 |
|---|---|---|---|
| 战区识别库 | 是什么？怎么用？怎么打？ | AI 副官式，短、准、结构化 | 遭遇、建造、观察关键行为 |
| 锚区档案 | 为什么存在？以前发生过什么？谁如何看待它？ | 多来源、有立场、有生活细节 | 战役、探索、关系与交叉证据 |

同一对象可以同时出现在两边。例如：

- 图鉴“战术格”直接说明可建造条件与特殊效果。
- 档案《地面上从来没有方格》讲述界面为何采用方格，以及旧版部署事故。

## 2. 一级分类

### 2.1 系统基础

- 基地车 / 主塔核心
- 锚定与锚区
- 工程节点 / 战术格
- 战备额度
- 战术目镜
- AI 战术副官

### 2.2 防御构筑

- 火力塔
- 控制塔
- 能量塔
- 工程辅助塔
- 塔楼升级与专精
- 索敌模式

筛选标签建议：`单体`、`范围`、`持续`、`控制`、`破甲`、`直线`、`支援`、`工程`、`对群`、`对首领`。

### 2.3 敌对目标

- 普通型
- 迅捷型
- 重装型
- 精英变体
- 首领 / 霸主

未来新增敌人时，除“普通 / 精英 / Boss”外还应提供功能标签，例如：`突进`、`装甲`、`干扰`、`远程`、`工程破坏`、`指挥节点`。

### 2.4 地形与节点

- 普通地面
- 阻塞地形
- 标准建造格
- 十二类特殊格
- 运行时改造节点（如永久霜寒格）

### 2.5 状态与协同

- 护甲与穿甲
- 减速与冻结
- 脆弱
- 燃烧与爆燃
- 破甲
- 击退
- 干扰、护盾与狂暴
- 回响、超频等构筑状态

### 2.6 战术支援

- 风车 / 旋刃拦截器
- 黑洞 / 坍缩阱
- 全塔超频
- 导弹雨
- 战场事件与预警协议

### 2.7 人物与智能体

- 当前战术副官
- 已接触的其他指挥人格
- 权限、托管与默契说明

角色详细背景仍以《锚区档案》的“人物与智能体”类为主，图鉴只保留可用权限、战术倾向与当前默契。

## 3. 解锁状态

关键玩法信息不能故意藏到刷取后期。建议每条识别记录分三阶段：

1. **初步识别**
   - 首次进入视野或首次获得建造权限时解锁。
   - 显示名称、外形、基础类型和最重要的危险提示。

2. **行为已确认**
   - 观察到关键技能、第一次建造使用或第一次施加对应状态后解锁。
   - 显示完整机制、推荐用途和应对方法。

3. **结构解析完成**
   - 击败、拆解、完成相关任务或取得可靠档案后解锁。
   - 显示详细数据、协同关系、副官备注与关联档案。

特殊情况可以显示：

- `数据状态：系统基础资料`
- `数据状态：初步识别`
- `数据状态：行为已确认`
- `数据状态：结构解析完成`
- `数据状态：结论存在争议`
- `数据状态：权限受限`

### 3.1 各类别推荐触发

| 类别 | 初次解锁 | 补全信息 |
|---|---|---|
| 系统基础 | 新游戏默认开放 | 教程或首次相关操作 |
| 塔楼 | 获得建造权限 | 首次建造、升级和选择分支 |
| 地图格 | 首次出现在当前地图 | 首次在该格建塔或触发效果 |
| 敌人 | 首次进入视野 | 观察关键行为、首次击败 |
| 状态 | 首次施加或受到 | 达成一次组合效果 |
| Boss | 进场即给关键危险信息 | 每个阶段第一次发动后补全 |
| 副官 | 角色注册表默认开放 | 默契变化、托管和战役记录 |

## 5. 首批识别记录

以下文本是第一版静态内容。伤害、价格、冷却、范围等易变数值不在这里手写，实际界面应从权威配置实时填充。

### SYS-001：锚定式机动基地

- **前线称呼**：基地车 / 主塔
- **分类**：系统基础、基地设施
- **数据状态**：系统基础资料

**识别概要**  
携带指挥舱、反应堆、制造线与工程群的机动平台。完成锚定后，其中央结构升起为主塔核心。

**战术功能**  
向整片锚区提供能源、建造、火控同步、敌我识别与战术副官运行环境。

**关键机制**  
普通敌人接触核心会造成伤害并释放破坏载荷；霸主接触核心会直接导致锚区失守。主塔拥有有限的近防反冲，但不能替代塔楼防线。

**副官备注（岚）**  
“地图上最重要的单位不是伤害最高的那一个，是所有其他单位还能继续工作的原因。”

**关联档案**：`ORI-001《锚定任务前简报》`、`ENG-002《展开顺序不得更改》`

### SYS-002：战术格

- **正式名称**：工程部署单元可视化
- **分类**：系统基础、地形与节点
- **数据状态**：系统基础资料

**识别概要**  
AI 对地下工程节点和部署权限的方形投影。

**关键机制**  
只有通过承重、供能和通信检查的节点才能部署塔楼。格线并不意味着世界由方块组成，敌人仍在连续地形上移动。

**副官备注（桃桃）**  
“把四十多项工程参数压成一个方格，是为了让你一眼知道能不能放，不是为了让地面看起来整齐。”

**关联档案**：`ENG-001《地面上从来没有方格》`、`INC-004《七码头炮座倾覆事故》`

### SYS-003：战备额度

- **前线称呼**：金币
- **分类**：系统基础、资源
- **数据状态**：系统基础资料

**识别概要**  
基地将材料、能源、制造工时、回收部件和补给信用合并计算后的统一额度。

**关键机制**  
用于建造、升级、工程重构和部分战术技能。击毁敌军后，回收无人机与战果认证系统会把可利用价值折算为额度。

**副官备注（桃桃）**  
“你可以继续叫它金币。只要别真去机器残骸里找硬币就好。”

**关联档案**：`LOG-003《关于金币图标的第六次投诉》`

### SYS-004：战术副官

- **分类**：人物与智能体、权限系统
- **数据状态**：系统基础资料

**识别概要**  
经本地认证、能够读取全锚区态势的战术人格。

**关键机制**  
副官在玩家移交托管权后可以执行建造、升级、出售和换防。所有操作遵循与玩家相同的资源和规则，不获得隐藏数值优势。

**副官备注（岚）**  
“你把决定交给我，不等于系统替我们免单。”

**关联档案**：`AI-003《副官是权限职位》`、`AI-007《等额权限审计》`

### SYS-005：副官视界协议

- **分类**：系统基础、指挥界面
- **数据状态**：完成副官认证后解锁

**识别概要**  
由当前副官负责生成的战术视觉层。格线、普通界面、扫描光谱和锚区环境色会随副官改变；真实地表与战斗规则不会因此变化。

**关键机制**  
岚使用青蓝色本地战术视界，桃桃使用粉色—暖珊瑚色后勤视界。可放置绿、不可放置红、危险警告、特殊格、敌军、Boss 阶段和塔种身份色保持一致。

**副官备注（岚）**  
“颜色可以换，警告的意思不许换。”

**关联档案**：`AI-011《把同一片战场看成两种颜色》`

### SYS-006：锚区启动序列

- **分类**：系统基础、基地设施
- **数据状态**：首次出击后解锁

**识别概要**  
空场确认、基地相位投送、主锚认证、副官扫描、战斗接管五个阶段的统称。

**关键机制**  
基地必须先抵达并锚定，AI 才能以主塔为扫描源建立战术格。地图显现代表工程权限被确认，不代表地面刚刚被制造。

**副官备注（桃桃）**  
“先把家放稳，再清点门口有什么。顺序反了，清单就没有意义啦。”

**关联档案**：`ORI-002《从空白到战区》`、`ENG-002《展开顺序不得更改》`

## 6. 地图格识别表

界面建议把“世界内名称”和“玩法效果”并列显示。世界内名称增加可信度，玩法效果必须直白。

| ID | 图鉴名称 | 识别说明 | 使用提示 |
|---|---|---|---|
| NODE-00 | 标准工程节点 | 各项指标达到标准，无额外偏置。 | 适合任意塔楼，便于稳定规划。 |
| NODE-01 | 峰值供能节点 | 把瞬时功率集中到武器，远距稳定余量下降。 | 适合射程足够、依赖高伤害的塔。 |
| NODE-02 | 远传阵列节点 | 接入高位传感或旧中继，扩大火控覆盖。 | 适合范围价值高的塔，注意输出与攻速代价。 |
| NODE-03 | 脉冲循环节点 | 电容可快速充放，但长距离输能不稳定。 | 适合高频攻击或近中程塔。 |
| NODE-04 | 多路汇流节点 | 多条能源和数据主干交汇。 | 全面强化，升级维护成本也更高。 |
| NODE-05 | 预制锁定基座 | 节点保留可用强化模块，但会与新塔永久熔接。 | 初始等级提高；出售无法正常返还。 |
| NODE-06 | 高保真认证节点 | 可上传完整击杀证据并换取更多战备额度。 | 适合稳定收割敌人的塔，基础属性略受带宽占用影响。 |
| NODE-07 | 制造直连节点 | 与基地制造线之间的物流损耗较低。 | 升级更便宜，适合准备长期投入的塔。 |
| NODE-08 | 磁轨移载节点 | 保留重型设备转运与重新锁定接口。 | 可以付费搬塔，适合局势变化大的位置。 |
| NODE-09 | 指令回响节点 | 介质会延迟复现一次火控波形。 | 追加攻击形态，但塔需降额并承担更高升级成本。 |
| NODE-12 | 延时回收节点 | 战利品先深度提炼，再周期结算。 | 收益延迟但总额提高，注意现金流空窗。 |
| NODE-13 | 失稳注入节点 | 攻击可向敌方核心写入过载标记。 | 击杀有概率引发爆裂，范围受限且升级更贵。 |
| NODE-14 | 低温相变节点 | 地层可长期维持低温场。 | 直接伤害附加减速；范围类伤害的耦合效果较弱。 |

所有特殊格在首次出现在地图时，应立即解锁完整玩法说明。玩家不应为了“保留神秘感”而在不知道代价的情况下建塔。

## 7. 塔楼识别表

### TWR-00：冰霜塔

- **标签**：控制、范围、冻结、脆弱
- **识别概要**：抽离范围内目标热量的相变控制塔。
- **关键机制**：基础攻击覆盖范围内敌人并减速；可专精为冻结路线或脆弱路线，后续能够生成冰刺、扩散霜寒格或强化穿甲协同。
- **使用建议**：放在多条路线交汇或火力密集区；冻结路线适合与爆燃火焰塔配合，脆弱路线适合高频与对甲输出。
- **副官备注（岚）**：“控制不是少打一发，是让其他塔多得到几次开火机会。”

### TWR-01：机枪塔

- **标签**：高频、多目标、清杂、暴击
- **识别概要**：以高速电磁发射和并发火控见长的通用塔。
- **关键机制**：升级后可同时处理更多目标；可选择暴击或破片路线。
- **使用建议**：适合早期补线和清理轻型目标。面对重甲时应搭配破甲、脆弱或暴击穿甲。
- **副官备注（桃桃）**：“它不负责把问题想复杂，只负责把简单问题处理得足够快。”

### TWR-02：加农炮

- **标签**：远程、范围、爆发、击退
- **识别概要**：向远距密集区投送智能重弹的区域火力塔。
- **关键机制**：爆炸覆盖多目标；可选择强化内圈爆破或形成持续爆炸区域。
- **使用建议**：优先覆盖路线交汇点。内圈路线要求落点精确，持续炮弹路线更适合封锁通道。
- **副官备注（岚）**：“范围大不代表随便放。炮弹落在敌群中心，才叫范围火力。”

### TWR-03：火焰塔

- **标签**：范围、持续、喷流、爆燃
- **识别概要**：投送高温工作介质并制造火区的近中程塔。
- **关键机制**：可改造成旋转或扇形喷火器，也可强化燃烧层数并与冻结触发爆燃。
- **使用建议**：靠近敌人会长时间经过的路线。爆燃分支必须配备可靠冻结来源。
- **副官备注（桃桃）**：“冰和火不是互相抵消。调度得当时，它们会替彼此完成最后一步。”

### TWR-04：激光塔

- **标签**：持续、多目标、破甲、折射
- **识别概要**：以多路连续光束追踪目标的火控阵列。
- **关键机制**：可持续烧蚀装甲，或让光束在相邻敌人之间折射。
- **使用建议**：破甲路线适合首领和高频火力网；折射路线适合密集敌群。集中索敌会带来额外负载，特定专精可消除代价。
- **副官备注（岚）**：“盯住同一块装甲，比把光照得满场都是更难，也更有用。”

### TWR-05：穿透激光

- **标签**：单发、直线、贯穿、对首领
- **识别概要**：大型电容驱动的超高功率线性光束。
- **关键机制**：一次射击伤害整条路径上的目标，攻击频率较低。
- **使用建议**：放置在长直线、入口轴线或首领与杂兵容易共线的位置。
- **副官备注（桃桃）**：“给它一条好直线，它会把这一整条路线都算成同一个目标。”

### TWR-06：水晶塔

- **标签**：巡行、持续、弯道覆盖、区域
- **识别概要**：操控悬浮晶体攻击单元沿射界边缘巡行。
- **关键机制**：晶体在外圈移动并持续伤害附近敌人，升级后可同时维持更多晶体。
- **使用建议**：覆盖弯道、环形路线和敌人长时间贴近射界边缘的位置。
- **副官备注（岚）**：“它的射程边缘不是警告线，是工作轨道。”

### TWR-07：火箭齐射

- **标签**：弹群、范围、爆发、对群
- **识别概要**：一轮投放多枚协同微型导弹的饱和火力平台。
- **关键机制**：多枚火箭分散落点并造成小范围爆炸。
- **使用建议**：适合高密度敌群和中程交汇点；回响节点能明显增加弹群规模。
- **副官备注（桃桃）**：“一枚导弹需要好准头，一整批导弹需要一份更好的落点清单。”

### TWR-08：充能塔

- **标签**：工程、节点改造、支援
- **识别概要**：勘测并重写相邻工程节点的地脉调谐设施。
- **关键机制**：选择相邻空闲标准格，再从三种可行特殊效果中确定一种；刷新候选的成本逐次增加。
- **使用建议**：先决定目标格未来放什么塔，再决定是否接受候选结果。不要只为即时增益浪费一个塔位。
- **副官备注（岚）**：“三选一不是抽奖，是地层只允许三种不会把管线烧穿的接法。”

### TWR-09：强化塔

- **标签**：工程、光环、协同、支援
- **识别概要**：为相邻构筑体提供授时、供能和火控同步的中继塔。
- **关键机制**：强化周围一格内塔楼的伤害、范围和攻速；重叠中继可以叠加，但仍受系统上限约束。
- **使用建议**：优先覆盖多个高投入或职责互补的塔。不要占用优质特殊格，因为辅助塔无法把个人地块增益转化成更强光环。
- **副官备注（桃桃）**：“它自己不抢战果，但能让周围每个班次都准时一点。”

## 8. 敌军识别表

### HOST-00：普通型突破机

- **标签**：通用、量产、破锚
- **数据状态**：首次目击即解锁
- **识别概要**：敌方最常见的标准化机械单位，耐久与速度均衡。
- **关键机制**：沿最短可行路径推进，到达主塔后释放破坏载荷。
- **应对建议**：任何塔都能处理，但数量上升时需要范围火力或多目标塔。
- **副官备注（岚）**：“普通只表示常见，不表示可以不管。”

### HOST-01：迅捷型突破机

- **标签**：突进、高速、轻型
- **识别概要**：减轻结构并强化驱动的高速批次。
- **关键机制**：生命较低但推进速度更快，容易从火力间隔中穿过。
- **应对建议**：使用减速、冻结、高频攻击或靠近主塔的补漏火力。
- **副官备注（桃桃）**：“它们最擅长证明两座看起来相连的塔，中间其实还有空档。”

### HOST-02：重装型突破机

- **标签**：装甲、高耐久、火力吸收
- **识别概要**：以厚重结构和高护甲换取推进稳定性的重型机体。
- **关键机制**：移动较慢，但会长时间占用防线输出并掩护后续敌军。
- **应对建议**：优先使用穿甲、破甲、脆弱和高单体伤害；避免让全线火力被单个目标拖住。
- **副官备注（岚）**：“它慢，是因为它认为自己有时间。别让它猜对。”

### HOST-E：精英变体

- **标签**：强化模板、跨机型、高威胁
- **数据状态**：首次精英信号后解锁
- **识别概要**：可附着在普通、迅捷和重装三种基础型号上的高规格生产模板。
- **关键机制**：体型、生命和速度显著提高；不是单独第四种敌人。
- **应对建议**：根据基础机型判断风险。精英迅捷威胁补漏，精英重装则考验持续对甲能力。
- **副官备注（桃桃）**：“先看它原本负责什么，再把‘更大、更硬、更快’加到那份工作上。”

### BOSS-00：霸主

- **分类**：首领、移动指挥节点
- **标签**：干扰、群体护盾、狂暴、破锚
- **数据状态**：阶段行为逐步补全

**识别概要**  
敌方大型移动授权节点，兼具突破机体和战场网络核心功能。

**关键机制**  
生命下降后依次启动塔楼干扰、群体护盾和自身加速。减速效果受到上限限制。抵达主塔即触发夺控，任务立即失败。

**应对建议**  
提前准备单体输出、破甲和首领优先索敌，同时保留少量塔处理护盾范围内的杂兵。最后阶段不要依赖无限减速拖延。

**副官备注（岚）**  
“它不是走在敌军中间。它就是那支敌军临时带到我们面前的网络。”

**关联档案**：`HOST-012《为什么它被称为霸主》`

## 12. 界面结构建议

正式版建议把当前 Esc 行为升级为暂停终端：

```text
PAUSE TERMINAL
├─ 继续任务
├─ 资料库
│  ├─ 战区识别库
│  └─ 锚区档案
├─ 系统设置
└─ 重新部署
```

战前指挥官选择界面可增加 `ARCHIVE // 档案库` 入口。这样角色 Dossier、默契记录和世界档案在视觉上属于同一套 `COMMANDER REGISTRY / SYSTEM LINK` 终端语言。

图鉴详情页建议采用三栏或两栏结构：

- 左侧：分类与条目列表。
- 中部：立绘 / 模型 / 图标、名称、标签、数据状态。
- 右侧：机制、动态数值、使用建议、协同关系和副官备注。
- 底部：`OPEN ARCHIVE` 跳转关联档案。

资料库整体沿用当前副官的视界协议：岚为青蓝，桃桃为粉色—暖珊瑚。图鉴中的规则语义色不随主题改变，确保同一特殊格、塔种或危险状态在两套界面中仍可立即辨认。

## 13. 数据实现约束

1. **机制与数值分离**：伤害、价格、范围、冷却等从运行时权威配置读取；手写内容只存稳定说明、标签和 lore。
2. **稳定 ID**：条目使用 `SYS-001`、`TWR-00`、`NODE-14` 等稳定标识，不使用显示名做存档键。
3. **本地化分离**：可借鉴现有 Commander 包，把解锁条件和引用关系放 core，把中文正文放 locale。
4. **版本化存档**：记录敌人目击、塔楼首次建造、地图格发现、状态触发和档案解锁；不要把长期系统只散落在多个 PlayerPrefs 键里。
5. **Boss 信息及时开放**：每个阶段第一次出现后立即补全，不要求玩家先失败才能看到应对方式。
6. **角色备注可替换**：规则正文保持一致，副官备注根据当前角色选择，以维持人格感而不制造机制歧义。
