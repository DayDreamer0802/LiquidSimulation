# 《锚区档案》内容与系统草案

> 系统代号：`ANCHOR ARCHIVE // 锚区档案`  
> 玩家俗称：设定集、记录库  
> 功能定位：保存任务简报、工程手册、权限审计、人员档案、事故报告与敌方残片。  
> 它回答“为什么会这样、谁留下了这段记录、还有什么没有查明”，不承担即时玩法教学。

## 1. 它不是另一份图鉴

《锚区档案》和《战区识别库》共用同一套终端入口，但面对的是两种不同需求：

| 系统 | 玩家打开它时想知道 | 正文形态 | 信息原则 |
|---|---|---|---|
| `TACTICAL INDEX // 战区识别库` | 这是什么？怎么用？怎么打？ | 结构化识别卡、实时数值、应对建议 | 关键玩法信息及时公开，不能故作神秘 |
| `ANCHOR ARCHIVE // 锚区档案` | 为什么存在？以前发生过什么？谁相信哪一种解释？ | 简报、日志、录音转写、审计和残片 | 允许有立场与空白，但必须标明可信度 |

例如，图鉴中的 `SYS-002 战术格` 应直接告诉玩家哪里可以建造；档案 `ENG-001《地面上从来没有方格》` 才解释地下工程节点、战术目镜，以及为什么绕过安全校验会出事故。

涉及伤害、价格、冷却、范围、持续时间等易变数值时，应跳转图鉴或从运行时读取，不在档案正文中抄写固定数字。

## 2. 档案的两条状态轴

“有没有解锁”与“这段话是否可靠”是两件事，界面必须分开显示。

### 2.1 解锁状态

- **公开资料**：任务开始前已经装入基地本地库。基础工程原理和安全规则属于这一档。
- **任务记录**：完成相应操作后生成，例如首次锚定、首次建塔、首次改造特殊节点。
- **关系记录**：选择副官、移交托管权或默契变化后开放。它们补充人物，不提供数值优势。
- **回收资料**：击毁敌方单位、完成事件或回收残片后取得。
- **交叉解密**：需要两条以上独立来源，或在击毁首领后才能还原。
- **权限受限**：玩家知道记录存在，但正文仍被删节。受限条目可以显示标题，不用假装它不存在。

关键玩法不能锁在这里。第一次遭遇敌人或特殊格时，图鉴照常完整提示；档案解锁的是背景与观点。

### 2.2 可信度标记

- `CONFIRMED // 已确认`：由当前玩法表现、我方工程资料或多源遥测直接支持。
- `INFERENCE // 可靠推定`：证据能够支持，但仍可能存在其他解释。
- `DISPUTED // 结论争议`：来源之间互相冲突，终端并列保留。
- `UNRESOLVED // 待解密`：有明确问题，没有足够证据，不允许正文替玩家偷偷下结论。

每条记录末尾都应列出“已确认”和“待解密”。神秘感来自诚实地留下问题，而不是把作者已经写死的答案伪装成乱码。

## 3. 一级分类与编号

| 编号前缀 | 分类 | 常见来源 |
|---|---|---|
| `ORI` | 任务与起源 | 战前简报、投送记录、任务授权 |
| `ENG` | 基地与工程 | 工程手册、维护规程、制造线日志 |
| `AI` | 人物与智能体 | 人格注册表、权限审计、对话记录 |
| `HOST` | 敌方网络 | 战场遥测、残片解析、威胁评估 |
| `INC` | 事故与异常 | 调查报告、违章记录、节点事故 |
| `LOG` | 前线生活 | 私人留言、后勤备忘、非正式录音 |
| `NET` | 断链与旧网络 | 认证记录、轨道链路、历史残卷 |

分类只表示入口，不代表来源立场。敌军残片可以反驳我方简报，私人日志也可能比正式报告更接近事实。

## 4. 界面与阅读语气

### 4.1 入口结构

```text
ARCHIVE TERMINAL // 资料库
├─ TACTICAL INDEX // 战区识别库
└─ ANCHOR ARCHIVE // 锚区档案
   ├─ 任务与起源
   ├─ 基地与工程
   ├─ 人物与智能体
   ├─ 敌方网络
   ├─ 事故与异常
   └─ 前线生活
```

档案详情页建议使用“索引—正文—证据”三段式：

- 左栏：分类、标题、解锁状态和未读标记。
- 中栏：文件正文，保留原来源的排版和说话方式。
- 右栏：可信度、来源链、已确认事实、待解密问题、关联图鉴。
- 页脚：当前副官的批注开关，以及 `OPEN TACTICAL INDEX` 跳转。

### 4.2 终端语气

- 系统提示短而克制：`新档案已恢复：ENG-002`。
- 正式工程文件准确、少修辞；私人记录可以口语化，但不人人都说谜语。
- 敌方残片尽量保留机器式字段和不完整上下文，不把乱码当装饰。
- 岚的批注偏结论、风险和边界；桃桃的批注偏流程、资源和协同。
- 副官批注是旁注，不得改写原文，也不能成为理解玩法的唯一来源。

### 4.3 解锁反馈

普通档案只在界面角落提示，不打断战斗。涉及副官个人记录时，可在战后结算显示一行角色回应；涉及霸主新阶段时，先由图鉴弹出危险提示，档案在战斗结束后再恢复，避免玩家边打首领边读长文。

## 7. 首批档案正文

### ORI-001《锚定任务前简报》

- **分类**：任务与起源
- **来源**：锚定式机动基地通用任务包
- **解锁条件**：新游戏默认开放
- **可信度**：`CONFIRMED // 已确认`

> 现场指挥官：  
> 本次任务不是占领整片区域。你的目标是在预定坐标建立一个能够被本地系统信任的锚区，并维持它，直到敌方最高授权节点被摧毁。  
>  
> 基地车将以战区投送方式进入坐标。投送完成后，移动反应堆、制造线、工程群和指挥舱仍处于收拢状态。不要在主锚完成载荷校验前调用重型构筑。  
>  
> 完成锚定后，基地车在任务系统中的称呼将切换为“主塔核心”。这不是换了一件设施，而是同一平台从行军状态进入满载工作状态。此时撤出主锚会同时切断塔楼供能、火控授时与敌我识别，战斗中不得执行。  
>  
> 敌方机械集群不会优先与你争夺每一寸地面。它们会把破坏载荷送向锚核。请把“守住中心”理解为维持整张防线继续存在，而不只是保护一栋建筑。

这里的“战区投送”是前线对整车传送流程的统称。可以确认基地并非在开场镜头中从地图边缘驶入；它在短暂失去外部参照后，于预定坐标重新建立本地定位。投送所依赖的远端设施、最大距离和能源来源仍受权限限制。

**已确认**

- 基地车、展开后的基地和主塔核心是同一平台的不同状态。
- 锚定后，塔楼依赖主塔提供供能、制造、授时和认证。
- 战斗中不能把基地拔锚当作撤退按钮。
- 普通突破单位会向锚核投送破坏载荷；霸主抵达则直接导致任务失败。

**待解密**

- 战区投送由仍在工作的轨道设施执行，还是由另一座地表锚站接力。
- 投送记录中被删除的出发坐标属于哪一套防卫网络。

**关联识别**：`SYS-001 锚定式机动基地`

### ORI-002《从空白到战区》

- **分类**：任务与起源
- **来源**：首次部署的战术视野录屏与系统事件流
- **解锁条件**：看完首次开场流程
- **可信度**：`CONFIRMED // 已确认`

录屏开始时，画面中什么也没有。这不代表战区真是一片虚无，而是指挥官的战术视觉层尚未获得可信坐标。系统拒绝用未校准的传感数据填满视野。

事件流应按以下顺序呈现：

1. **空地 / 无可信图层**：只保留低亮度背景与链路噪声，界面显示 `LOCAL FRAME NOT ESTABLISHED`。
2. **基地投送**：基地车在预定点完成空间重定位，轮廓先以高亮晶格锁定，随后实体图层接管。
3. **主锚接触**：中央结构下沉并承载，基地开始建立本地坐标、供能零点与敌我识别根证书。
4. **工程扫描**：扫描波从锚核向外扩散；地表、边界和旧设施逐段进入可信图层。
5. **节点标记**：AI 将合格工程节点渲染为战术格，并用不同颜色标出异常条件；无法认证的区域不开放建造权限。
6. **战斗准备**：制造线、塔楼目录、战备额度和副官控制通道依次上线，系统才显示 `ANCHOR READY // 准备战斗`。

开场中看到的水晶显形、边界闪光和格线展开，都是战术目镜对“数据已被验证”的表达。地表没有在一秒钟内凭空长出来；基地也没有把世界变成棋盘。

> **岚 / 录屏批注**  
> “先确认自己站在哪里，再讨论从哪边开火。这个顺序没有浪费时间。”

> **桃桃 / 录屏批注**  
> “看到最后那句‘准备战斗’再花钱。前面的亮光都是工程组还在点名。”

**已确认**

- 空白开场表示战术图层尚未建立，不表示地图是模拟出来的。
- 扫描负责验证地表、边界和工程节点；AI负责把结果翻译成可读界面。
- 主塔与地图的显形效果可以在演出中压缩，但设定顺序是投送、锚定、扫描、开放建造。

**待解密**

- 投送过程中那段短暂的全传感器静默是技术必要，还是有一部分记录被主动遮蔽。

**关联识别**：`SYS-001`、`SYS-002`

### ENG-001《地面上从来没有方格》

- **分类**：基地与工程
- **来源**：工程新兵课程，第九次修订
- **解锁条件**：首次进入建造模式
- **可信度**：`CONFIRMED // 已确认`

> 你在战术目镜里看到的是部署权限，不是地貌。  
>  
> 一块地面能否承受构筑体，至少取决于地层承载、锚桩咬合、主供能距离、冷却回路、弹药通路、数据授时和敌我识别握手。把这些结果同时塞进视野，只会让指挥官在第一座塔落地前看见一片工程参数。  
>  
> 因此系统只给出一个方格：绿色表示这组条件目前成立，红色表示至少一项失败，特殊颜色表示条件成立但存在可利用的偏置。  
>  
> 方格边缘不是墙。轻型单位在连续地形上移动，导航系统也使用远比部署格更细的采样。只有大型构筑体必须服从标准工程单元。

节点的固定桩、检修盖和能量指示器可能真实可见；把整块地面框成正方形的亮线则属于AI战术图层。关闭目镜，不会让地下管线消失，也不会让格线留在泥土上。

**已确认**

- 工程节点真实存在；战术格是AI对节点状态和权限的可视化。
- 塔楼按标准大格部署，敌军仍在连续地形上进行细致寻路。
- “看起来平坦”不足以证明一处位置可以建塔。

**待解密**

- 部分旧设施为何使用与现行锚网完全相同的标准接口。

**关联识别**：`SYS-002 战术格`、`NODE-00 标准工程节点`

### ENG-002《展开顺序不得更改》

- **分类**：基地与工程
- **来源**：锚定式机动基地维护规程，安全页置顶
- **解锁条件**：完成首次锚定演出
- **可信度**：`CONFIRMED // 已确认`

锚定不是把四只支脚放到地上。标准展开顺序如下：

1. 主锚钻入稳定层，基地车将自身重量和反应堆振动转移到深层地基。
2. 地下微型工程钻机从主锚向外展开，沿预定走廊寻找可咬合岩层。
3. 工程群在合格位置打入地基固定桩；每组固定桩都要承受塔身、自身振动和连续开火的后坐力。
4. 供能管、冷却管、弹药输送和数据纤维沿同一路由接入节点。地面看到的光只表示接口已握手，不代表能源在空气中流动。
5. AI逐格执行承重和链路校验。只有通过的节点才进入建造清单。
6. 主塔核心升起，制造线从运输锁定切换到战斗权限，整片区域正式成为锚区。

若先接通能源、后确认锚桩，塔楼第一次满功率开火就可能把自身从地基上拔出来；若先开放火控、后完成授时，数座塔会把同一个目标识别成不同单位。规程中的顺序不是仪式，是事故名单压缩成的六行文字。

**已确认**

- 每个合格节点同时需要固定桩、供能/冷却/弹药管和数据接口。
- 固定桩负责承载和后坐力，管线负责让塔楼持续运行。
- 锚核是整张网络的源头，锚定完成后无法在战斗中安全拔除。

**待解密**

- 微型工程群最初由哪一时期的统一防卫网络设计。

**关联识别**：`SYS-001`、`SYS-002`

### ENG-003《一座塔如何在数秒内到岗》

- **分类**：基地与工程
- **来源**：制造线参观许可稿，工程部门删改版
- **解锁条件**：首次建造任意塔楼
- **可信度**：`CONFIRMED // 已确认`

塔楼不是从主塔底下整座传送出来，也不是一束光变成了金属。

基地在行军状态就携带标准炮座、驱动骨架、工作介质和若干高价值武器核心。建造命令下达后，制造线打印缺失框架，地下输送通道把预制模块送到目标节点，工程无人机完成锁定。战术目镜中的旋转框架负责显示校准边界，全息晶格显示当前已经通过检查的结构层；当实体渲染接管时，意味着塔楼获准开火。

快速部署依赖高度标准化。所有塔共享节点接口、授时协议和基础诊断，但武器模块并不相同。升级意味着更换炮芯、扩容冷却、增加弹体通道或写入新的火控模块；专精分支之所以不能随意来回切换，是因为二级改装往往已经改变内部管路与空间布局。

出售只能回收部分投入。打入地层的锁固件、已经烧蚀的部件、消耗掉的工作介质和现场校准时间，不会因为按下“出售”就恢复成原料。

**已确认**

- 建造视觉是快速制造、模块运输、工程锁定和AI校准的合成表现。
- 塔楼依赖实体构件，不是纯全息武器。
- 升级和分支对应硬件与固件改造；出售存在不可回收损耗。

**待解密**

- 水晶攻击单元的核心材料能否由基地完全制造，还是只能依赖库存与回收。

**关联识别**：`TWR-00` 至 `TWR-09`

### ENG-004《特殊节点不是奖励地板》

- **分类**：基地与工程
- **来源**：节点勘测员内部备忘
- **解锁条件**：首次发现任意特殊格
- **可信度**：`CONFIRMED // 已确认`

前线喜欢把发亮的格子都叫“强化格”，这个称呼方便，但不准确。某些节点确实拥有更高能源通量；另一些只是频谱偏向远距传感、保留旧制造接口、拥有更完整的战果认证链，或处于会复现火控波形的异常介质上。

因此，特殊节点往往同时给出收益与代价。峰值功率可能挤占传感余量，远传阵列可能分走武器带宽，旧基座可以直接提供强化模块却无法完整拆解，回响介质能够重复攻击也要求构筑体降额运行。颜色越亮，不代表可以不看说明。

充能塔也不是摇奖机。它对相邻节点做深层勘测，再从当地地层、遗留接口和当前锚网负载中找出三种稳定方案。所谓“刷新”，是付费推翻一轮工程结论并继续向下重构；次数越多，已经做过的无效工作越难回收。

档案将特殊节点按原因分为五类：高通量、频谱偏置、工程遗留、协议权限和介质异常。图鉴仍按实际玩法效果显示，不要求玩家先记住工程分类。

**已确认**

- 标准格之外存在十二类已投入使用的特殊节点效果。
- 特殊节点并非全部“能量更高”，且不少效果带有明确代价。
- 充能塔只改变相邻可用节点，并从当前可行方案中提供三项候选。

**待解密**

- 指令回响和低温相变介质是自然现象、旧时代工程产物，还是两者共同作用。

**关联识别**：`NODE-01` 至 `NODE-14`、`TWR-08 充能塔`

### HOST-001《它们为什么只向中心推进》

- **分类**：敌方网络
- **来源**：多批次残片、路径遥测与主塔接触记录的合并分析
- **解锁条件**：首次击毁任意敌军

目前确认的敌军都是机械单位。普通、迅捷和重装不是三个互不相关的种族，而是同一破锚任务下的三类标准机体：通用批次负责维持数量，高速批次寻找火力空窗，重装批次消耗防线的持续输出。精英信号则会把更高规格的结构、驱动与权限模板附着到这些基础机型上，它不是第四种独立敌人。

它们很少停下来攻击沿途塔楼。不是因为看不见，而是因为摧毁单塔不如切断锚核有效。普通单位抵达核心后释放一次性破坏载荷并退出战场；后续机群会沿仍然可行的路线继续推进。

敌方批次会随战斗持续而变得更难处理。遥测更支持“生产端根据本局数据调整后续批次”，不支持同一台机体在行进中突然进化。它们的外壳与我方构筑存在若干相似接口，说明双方可能继承自同一技术体系，但这仍不足以证明敌方是谁。

敌军外观上的枪械或挂点不应被档案描述成当前不存在的远程攻击。战场只确认了推进、载荷接触和首领的区域协议能力。

**已确认**

- 当前敌军全部是机械单位，基础机型为普通、迅捷、重装三类。
- 精英是可附着于基础机型的强化模板。
- 普通敌军以锚核为终点，不会在当前玩法中沿途远程攻击塔楼。
- 后续批次随战斗时间获得适应性强化。

**待解密**

- 生产端是全自动设施，还是仍有人类或战术人格发出任务。
- 敌我双方为何保留同源接口与相似的防卫协议。
- 对方的战术显示中，我们是否同样被标记为“红方”。

**关联识别**：`HOST-00`、`HOST-01`、`HOST-02`、`HOST-E`

### HOST-012《为什么它被称为霸主》

- **分类**：敌方网络
- **来源**：首领遥测、敌方授权树残片、锚核防火墙记录
- **解锁条件**：霸主首次进场；击毁后恢复末段
- **可信度**：行为 `CONFIRMED`，命名来源 `INFERENCE`

“霸主”不是对体型的感叹。敌方授权树残片显示，该单位在局部网络中拥有压过普通机群的调度等级。我们的系统把那组权限关系译成了 `OVERLORD`，前线随后把它简称为霸主。

它是一座主动向前推进的移动网络节点。外层结构受损后，它会依次释放三类能力：先扰乱锚网授时，使附近塔楼的攻击循环变慢；再展开区域护盾，降低范围内敌军受到的伤害；最后关闭部分稳定与散热余量，把剩余功率送入驱动系统。最后阶段推进加快，但它仍会受到系统规定上限内的控制效果。

霸主抵达主塔造成的不是一次更大的普通撞击。锚核防火墙记录显示，它会尝试以高权限夺控模块接入本地认证链。无论最终结果是改写还是烧毁，防线都会立刻失去可信根，因此任务判定为失败。

击毁霸主会让当前锚区内的敌方最高授权节点消失，所以它可以作为关卡胜利目标。但“最高授权节点”不等于整个敌方网络的唯一核心；没有证据说明摧毁一台霸主就能结束断链战争。

> **岚 / 战后批注**  
> “它不是走在敌军中间。它就是那支敌军临时带到我们面前的网络。”

**已确认**

- 霸主具有干扰、群体护盾和最终加速三个依次开启的阶段能力。
- 霸主接触锚核会触发夺控或认证链毁坏，任务立即失败。
- 摧毁霸主可以切断本锚区的敌方最高授权节点。

**待解密**

- `OVERLORD` 是敌方自称、旧系统权限字段，还是我方翻译器的选择。
- 霸主是否拥有独立人格，或只是更高层网络的移动执行器。
- 同一权限等级下是否存在其他外形与能力完全不同的首领单位。

**关联识别**：`BOSS-00 霸主`

> **根因**：地表平整度被错误地当作承载能力；临时供电成功被错误地当作节点完整。  
> **整改**：战斗权限下禁止绕过承重、供能、冷却和数据握手。目镜只显示通过完整校验的部署格。

报告最后附了一张被反复引用的照片：炮口仍然指向敌军来向，整座炮塔却斜着沉进水里。工程学院把它放在“为什么系统不让你随便造塔”的第一页。

**已确认**

- 塔楼需要经过认证的固定桩和完整管线，单纯接上电源不足以安全开火。
- 战术格外并非绝对无法放置物体，而是无法保证标准构筑体持续作战；游戏中的安全联锁会直接禁止。
- 事故没有造成伤亡，原因是构筑体及时远程停机。

**待解密**

- 调查附件中关于码头下方“非民用旧接口”的一页为何被撤回。

**关联识别**：`SYS-002 战术格`

## 8. 可继续扩写的档案组

首批条目建立了玩家理解一局战斗所需的因果链。后续扩写应优先形成互相印证的小组，而不是不断增加孤立名词。

### 8.1 “断链日”组

- `NET-001《最后一份共同证书》`
- `NET-004《双方都把自己标成蓝色》`
- `LOG-011《轨道上还有人在回信吗》`

这组档案在宏观设定拍板前保持 `DISPUTED` 或 `UNRESOLVED`，不得提前确定敌方仍有人类。

### 8.2 “构筑谱系”组

- 冰霜与火焰设备为何能形成爆燃协同。
- 激光烧蚀为何能够永久削弱装甲。
- 水晶攻击单元的材料来源。
- 充能塔和强化塔为何会随同类数量增加而更昂贵。

这些条目解释技术和使用文化，不复制塔楼图鉴的分支表。

### 8.3 “任务余波”组

- 首次主塔受损后的维修记录。
- 第一次精英信号的来源分析。
- 霸主击毁后的授权树静默时长。
- 岚或桃桃对同一战报的不同批注。

任务余波适合在结算页面解锁，让世界观成为玩家行为留下的记录，而不是开局一次性塞进菜单的百科全书。

## 9. 写作与实现约束

1. **档案不替代图鉴**：敌人危险能力、特殊格代价和Boss阶段必须先在图鉴公开。
2. **不复制动态数值**：档案只描述稳定因果，具体数值由运行时配置和图鉴生成。
3. **来源必须有身份**：工程规程、后勤邮件和敌军残片要有不同语气，不能都是全知作者。
4. **明确事实等级**：涉及断链原因、敌方是否有人类、传送来源和AI人格本质时必须标记待解密。
5. **不虚构未实现攻击**：当前普通敌军只推进并在接触主塔时造成效果；档案不得擅自增加远程射击、偷塔或拆塔行为。
6. **不承诺未实现功能**：档案里的投送、回收无人机和地下输送是玩法解释，不自动等于新增可操作单位。
7. **角色不提供作弊解释**：岚与桃桃的区别是人格、决策倾向和表达，不是隐藏伤害或资源倍率。
8. **格子不是世界本体**：工程节点真实、战术格可视化，这条统一口径不得在其他文本中反转。
9. **失败保持严肃**：在周目结构正式确定前，不把重试写成时间回溯、克隆复活或模拟训练。
10. **关联使用稳定ID**：存档保存解锁状态时使用 `ORI-001`、`ENG-002` 等编号，不使用显示标题作键。
